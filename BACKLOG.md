# Бэклог: «Панда будет?»

Мобильное приложение-тренажёр игры «Что? Где? Когда?» + собственная мини-игра. Название — «Панда будет?» (решено 29.08.2026, личная отсылка) — рабочее название закреплено.
Бесплатное некоммерческое, Flutter, дистрибуция по образцу `~/speech-rehab` (APK вручную, в дальнейшем OTA).

**Источник правды — этот файл.** Ссылка на память Claude (`project_chgk_trainer_app.md`) устарела: файла нет, память пуста. Всё, что нужно для старта новой сессии, держим здесь.

**Состав MVP (пересмотрен 29.08.2026, см. «Ревизия концепта»):** «Классика» + «Вопрос дня». «Бинго» и «Тренажёр рассуждений» — сразу после, но не в первой сборке. «Своя игра» (T6) — отдельная большая задача на потом.

## Ревизия концепта (29.08.2026)

Разбор концепта целиком. Решения ниже **имеют приоритет** над более ранними разделами T2a/T3/T4/T9 там, где противоречат им.

### Что поменялось по существу

**1. Бинарная самооценка отравляет всю адаптивность.** `«Верно»/«Не ответил»` после показа ответа — хиндсайт-байес («ну я почти это и подумал»). Этим числом кормятся порог 70% в T3, «% верных» в T9 и подбор в T4. Исправления, все в T2a:
- **Фиксация версии до раскрытия** — одно `TextField`, игрок записывает версию прежде чем увидит ответ. Автопроверки не нужно: сам факт записи снимает байес и оставляет след рассуждения.
- **Три исхода вместо двух:** `взял` / `почти — не хватило шага` / `не взял`. Средняя корзина диагностически самая ценная.
- **Подсказка автопроверки** (не вердикт): нормализация + fuzzy-match по `answer` + `acceptance` (заполнены у 92-98%) предзаполняет кнопку самооценки.

**2. Промах сейчас ничему не учит.** Не взял → посмотрел ответ → следующий вопрос — это пассивный просмотр. Вводим:
- **Подсказка по запросу в любом режиме.** С 30-й секунды доступна кнопка — подсвечивается фраза-триггер / называется приём. Исход пишется как «взял с подсказкой» (`hintUsed: true`). Разметка T4 окупается во всех режимах, а не в одном.
- **Блокнот версий на время таймера** — минута перестаёт быть пустой, после раскрытия видно, на каком шаге свернул не туда.
- **Проваленный вопрос обязан вернуться** — интервальное повторение не только приёмов, но и конкретных вопросов. После T10 это просто запрос к журналу.

**3. Бинго тренирует не тот навык (пересматривает T3).** В текущем дизайне тема известна до вопроса — то есть узнавание клише, ради которого режим и существует, выключено. Плюс данные не тянут: 635 вопросов / 135 тем ≈ 4.7 на тему, 11 тем с одним вопросом, «Буратино» с нулём; порог `correct/seen ≥ 70%` при одном вопросе — подбрасывание монетки.
**Новая механика:** клетка = тема-**кандидат**. Показывается вопрос → игрок выбирает, к какой из 9 клише-тем сетки он относится (обязателен вариант «ни к одной», иначе выбор методом исключения) → угадал, клетка закрашивается. Работает при одном вопросе на тему, сетка становится пространством ответов, режим перестаёт быть переодетой «Классикой».

**4. Приём — это тег вопроса, а не режим (пересматривает T4).** Разметка дорогая → должна работать везде: подсказка в «Классике», причина промаха, карта слабых мест. «Тренажёр рассуждений» превращается в плейлист поверх общего движка. Следствие: T4 уходит с критического пути — ценность появляется с первых ~20 размеченных вопросов, а не после всех 19 приёмов.

**5. Разметку не искать руками.** Комментарии часто прямо называют приём — грепом по `comment`+`question`: замена 1053, перевод 169, игра слов/омоним 41, аббревиатура 32, анаграмма 18, палиндром 15. Человек только подтверждает и отмечает фразу-триггер.
**Жёсткое ограничение:** `complexity` есть только у 2943 из 9280 (32%), а дизайн T4 требует сортировать вопросы внутри приёма по сложности → **пул для разметки фильтровать по наличию `complexity`**, иначе получим размеченное, но несортируемое. Пересечение «маркер + complexity» = 575 вопросов, на MVP-таксономию хватает.
**Разметка встроена в игру:** тап по фразе-триггеру (шаг 4 цикла T4) пишется в журнал как предложение разметки. Две недели собственного использования = сотни размеченных вопросов бесплатно.

**6. Семантика `complexity` не подтверждена.** В T5 записано «похоже на % непройденности по двум замерам». Показывать «этот вопрос взяли только N% команд» на основании *похоже* нельзя — это фактическое утверждение о турнире. Либо сверить с известным пакетом до релиза, либо формулировать относительно: «сложнее, чем 70% вопросов базы».

**7. Диагностику дешевле спросить, чем вычислить.** Один тап после раскрытия: **что помешало?** → `не знал факта` / `знал, но не связал` / `не увидел приём` / `не хватило времени`. Работает во всех режимах без разметки и различает то, что «% верных» смешивает: пробел в эрудиции, в раскрутке и в скорости — три разные тренировки.

**8. Ретеншен: streak+XP берут у NYT не тот урок (дополняет T9).** Крючок NYT Games — не XP, а один конечный общий объект на сегодня. Отсюда T12 «Вопрос дня». Плюс **у сессии должен быть конец**: раунд из 5 вопросов с итоговым экраном, а не бесконечная лента. Итог раунда — естественное место для диагностики, реплики панды и «ещё раунд?».

**9. Панда: одно правило (дополняет T8).** **Панда не язвит по поводу неверного ответа.** Язвит по всему остальному — медленно читаешь, снова зашёл в 2 ночи, третий раз подряд на одном приёме. На промахе — сухо по делу или в солидарность («этот и командой не берут»). Иначе получаем насмешку ровно в момент неудачи, чего не делает даже сова Duolingo. «Редкой искренности» нужен явный бюджет — не чаще 1 реплики из ~30. Объём банка: ~10 строк × 8 моментов = ~80 до заметных повторов.

**10. Свежесть контента против дистрибуции.** Главный аргумент против db.chgk.info — стагнация с 18.10.2024, но APK ставится вручную и контент замерзает на версию → через год та же стагнация, только своя. `gotquestions_dump.json` = 10.6 МБ, бинго = 0.8 МБ; после T11 и выкидывания неиспользуемых полей спокойно бандлится. **OTA нужен для обновления, а не для первого запуска:** офлайн из коробки + подтягивание свежего пакета при наличии сети.

**11. Порядок работ.** Сейчас в репозитории меню с тремя заглушками и 9915 вопросов, которые никто не читает. T2a — фактический критический путь.
`T10 → T11 → T2a → «Классика» end-to-end → T12 → две недели пользоваться самому → выбирать второй режим.`

**12. Критерии успеха MVP (назвать заранее, иначе решение о втором режиме принимается по настроению):**
- возвращаюсь ≥5 дней из 7 без напоминания;
- растёт доля «взял» на собственных слабых приёмах;
- ловлю узнавание клише на живой игре.

### Анти-бэклог — чего не делать

Записано наравне с задачами, чтобы не возвращаться к обсуждению:
- командный / онлайн-режим, аккаунты, облачная синхронизация, лидерборды;
- **генерация вопросов LLM** — соблазн максимальный, качество ЧГК-вопроса LLM не вытягивает, а один плохой сгенерированный вопрос обесценивает весь корпус в глазах игрока. LLM допустима **только как ассистент разметки** с ручной проверкой (см. п. 5).

## T10 — журнал событий (решать ДО T2a)

**Проблема:** в текущем дизайне три независимых хранилища прогресса — темы в T3 (`shared_preferences`), XP/streak в T9, Leitner в T4. Три источника правды → гарантированный рассинхрон, и каждая новая метрика требует нового поля.

**Решение:** одно append-only событие на каждый ответ:
```
{ts, questionId, mode, theme?, tehnika?, verdict, hintUsed, secondsUsed, reason?, userAnswer?}
```
`verdict`: `taken | almost | missed`. `reason` — из п. 7 ревизии. Все метрики — производные (свёртка журнала), ничего не хранится параллельно: «X/139 тем», «X/19 приёмов», % верных, streak, карта слабых мест, отбор проваленных на повтор. Новую метрику можно ввести задним числом, пересчитав историю.

**Почему до T2a:** T2a — единственный писатель в журнал, его колбэк `onComplete` меняется с `(correct: bool)` на полное событие. Заложить сразу — бесплатно, ретрофитить — переписывать все режимы.

## T11 — санитайзер дампов

**Проблема (замерено 29.08.2026):** непригодны для одиночного текстового формата 618 из 9280 gq (6%) и **80 из 635 бинго (12%)**. В бинго это каждый восьмой при среднем 4.7 вопроса на тему — тема из 1 вопроса может оказаться темой из 0 рабочих. Фильтровать **до** формирования сетки 3×3, не в рантайме.

**Чинится, не выбрасывается:** инструкции ведущему (`[Ведущему: ...]`, `[Чтецу: ...]` — 270 gq + 39 бинго) — это префикс в квадратных скобках, вырезается регуляркой, вопрос остаётся рабочим.

**Выбрасывается из MVP:** раздатки и картинки (156 gq + 30 бинго), аудио/видео (59 + 13), дуплеты и блицы (155 + 2), пустой текст (1), вопросы без ответа (2 gq).

**Помечать, а не удалять:** отбракованные записи остаются в дампе с полем-причиной (`excluded: "handout" | "media" | "duplet" | ...`), чтобы T13 не пришлось краулить заново ради списка.

## T12 — «Вопрос дня»

**Зачем:** streak и XP — не крючок, а следствие. Крючок NYT Games — один конечный общий объект на сегодня: сегодняшний вопрос кончается, и в этом всё дело. Контент-цена нулевая (выбор из имеющегося), ритуал формируется сам.

**Механика:** один и тот же вопрос для всех в сутки (детерминированный выбор по дате — сид от `YYYY-MM-DD`, никакого сервера не нужно), реплика панды к нему, локальная история пройденных дней. Одна попытка в день.

**Задел на потом:** отсюда естественно вырастает шеринг результата без спойлеров (по образцу Wordle) — но в MVP не делаем, см. анти-бэклог про социальные функции.

## T3 — дизайн режима «Бинго» (зафиксировано 29.08.2026)

> ⚠️ **Механика пересмотрена** — см. п. 3 «Ревизии концепта»: клетка = тема-кандидат, игрок угадывает тему по вопросу. Прогресс по темам — не отдельное хранилище, а свёртка журнала T10 (п. 1 ревизии).

**Схема записи вопроса (контракт T1↔T3):** плоский список (не вложенность по темам), у каждой записи свой `id` = слаг темы (транслит, kebab-case) + порядковый номер вопроса внутри темы. Поля: `id, theme, tournament, question, answer, acceptance, comment, sources[], author`.

**Прогресс и адаптивный подбор тем:** локально в `shared_preferences`, одна JSON-строка `{theme: {seen, correct, shownIds[]}}`. `shownIds` — только чтобы не повторять один и тот же вопрос подряд внутри темы, пока есть другие; полный per-question mastery-трекинг признан избыточным для MVP.

**Порог «неосвоенности»:** тема неосвоенная, если `seen == 0` ИЛИ `correct/seen < 70%`; иначе — освоенная.

**Генерация сетки 3×3:** 6 неосвоенных / 3 освоенных темы на 9 клеток, перемешаны случайно (освоенные — «опорные» клетки, чтобы линии реально собирались). У нового пользователя (везде `seen==0`) — вырожденный случай, сетка из 9 неосвоенных, отдельного правила не нужно.

**Основной цикл:** сетка тем → тап по клетке → переиспользуем экран/движок вопроса T2a (вопрос → таймер 60 сек → Ответ/Зачёт/Комментарий/Источник/Автор → самооценка «Ответил верно»/«Не ответил») → `onComplete(correct: bool)` обновляет клетку в памяти экрана сетки + дописывает результат обратно в `shared_preferences` → закрашивание клетки → проверка линии → анимация «Бинго!».

**Стек состояния:** обычный `StatefulWidget`, без Provider/Riverpod/Bloc — сверено с `pubspec.yaml` после T2 (там пока только `flutter`/`flutter_test`). Экран сетки читает прогресс при открытии, держит 9 клеток у себя в памяти, пишет обратно после каждого вопроса.

**Блокер снят 29.08.2026:** T1 готова — `data/bingo_questions.json`, 635 вопросов по 135 темам, поля соответствуют контракту (`id, theme, tournament, question, answer, acceptance, comment, sources[], author`). 11 тем совсем тонкие (только 1 вопрос), у темы «Буратино» вопросов нет вообще (в источнике только определение) — учитывать при формировании сетки 3×3, если тема окажется без достаточного числа вопросов для повторных попыток.

## T4 — дизайн «Тренажёра рассуждений» (зафиксировано 29.08.2026)

> ⚠️ **Пересмотрено** — см. пп. 4-6 «Ревизии концепта»: приём становится тегом вопроса (работает во всех режимах), пул разметки фильтруется по наличию `complexity`, формулировку про «N% команд» не показывать без сверки.

**Отличие от «Классики»:** не случайные вопросы, а прохождение по конечному списку ~19 приёмов из таксономии Савченкова (12 подтипов ложного хода: слово/название/человек/животное/произведение как другая сущность, вымысел и метафора как реальность, замена, часть слова как слово, ненужная информация; плюс аналогия, тавтология, перевод для ответа, учесть имя, аббревиатура, подсчёт сущностей, палиндром — общеупотребимые в ЧГК-сообществе термины, не копия книги).

**Основной цикл на один приём:**
1. Короткая карточка-урок своими словами: что за приём, как выглядит в тексте (1-2 предложения).
2. Реальный вопрос, заранее помеченный тегом этого приёма (используем движок T2a — вопрос/таймер/раскрытие ответа).
3. Перед показом названия приёма — активное угадывание: 3-4 варианта на выбор «какой приём тут использован?» (эффект тестирования сильнее пассивного чтения).
4. После раскрытия — попросить **тапнуть в тексте вопроса** ту фразу-триггер, которая была маркером приёма (при разметке помечаем не только категорию, но и конкретную фразу).
5. Показать контекст сложности: «этот вопрос взяли только N% команд» — используем **реальный числовой рейтинг сложности на уровне конкретного вопроса** (уточнено 29.08.2026: есть только в gotquestions.online, поле `complexity` — два числа на вопрос, похоже на % непройденности по двум замерам; у db.chgk.info такого поля нет вообще, ни на вопрос, ни на пакет), и сортируем вопросы внутри приёма от простых к сложным по этому показателю.

**Между приёмами / долгосрочная механика:**
- Интервальное повторение слабых приёмов (Leitner-подобная логика: чаще возвращаем то, где чаще ошибался).
- Личная карта слабых мест — прямая визуализация «ты чаще всего путаешься в приёме X», не только скрытый алгоритм подбора.
- «Приём недели» — не открывать все ~19 сразу, а по одному за раз (управляемый темп, привязка к ритуалу «одна задача в день/неделю» как у NYT Games).
- Периодический экзамен-гаунтлет: быстрый микс уже изученных приёмов без подсказки какой где — тест переноса навыка, никакого нового контента не требует.
- «Проверка вслепую»: время от времени вопрос без подсказки приёма вообще (как в «Классике») — мостик обратно в обычный режим, финальная проверка что распознавание работает без опоры на подсказки интерфейса.

**Контент-цена (реальная, не бесплатная надстройка):** на каждый использованный реальный вопрос нужно вручную разметить — (а) категорию приёма, (б) фразу-триггер в тексте; (в) % взятия теперь приходит автоматически вместе с вопросом из дампа T5 (поле `complexity`), разметки не требует. Плюс ~19 своих коротких объяснений приёмов.

**Отложено в бэклог как более дорогая/продвинутая идея, не MVP:** «разбор от противного» — сначала показать только ответ, попросить угадать каким приёмом его могли обыграть, потом раскрыть реальный вопрос (тренирует генеративный навык «взгляд редактора», а не только распознавание).

## T9 — дизайн сквозной прогрессии (зафиксировано 29.08.2026)

> ⚠️ **Дополнено** — см. пп. 7-8 «Ревизии концепта»: метрики считаются из журнала T10, добавлены диагностика «что помешало», конечный раунд из 5 вопросов и «Вопрос дня» (T12) как основной ритуал вместо XP-гринда.

**Принцип:** единый профиль сверху + drill-down в нативную метрику каждого режима снизу — не подменяем специфичный смысл метрики режима одним общим числом, а дополняем его.

**Главный экран профиля:**
- Общий streak (дней подряд позанимался хоть в одном режиме) + общий XP/уровень как индикатор суммарной вовлечённости.
- Карточки по режимам, каждая — своя нативная метрика, тап → отдельный экран с деталями:
  - Бинго → «X/139 тем освоено» (мини-сетка).
  - Тренажёр рассуждений → «X/19 приёмов освоено» (скилл-лист).
  - Классика → % верных за всё время / сколько вопросов пройдено.

**Начисление (максимально просто на MVP):** +XP фиксированной величиной (например +10) за каждый верный ответ в любом режиме, день отмечается как активный для streak. Кривая уровней не проектируется заранее — линейная шкала, при необходимости усложнить позже.

**Технический контракт:** не конфликтует с уже решённым в T3 (свой прогресс по темам в `shared_preferences`) — колбэк `onComplete(correct: bool)` из T2a дополнительно дёргает общий профиль-стор, помимо того что уже пишет каждый режим себе. T2a ещё не начат — контракт закладывается сразу, переделывать нечего.

## T8 — визуальный тон и персонаж панды (зафиксировано 29.08.2026)

> ⚠️ **Дополнено** — см. п. 9 «Ревизии концепта»: панда никогда не язвит по поводу неверного ответа; «редкой искренности» задан бюджет.

**Персонаж (ключевое):** панда — не мотиватор-клакер уровня совы Duolingo, а **противоречивый сокомандник**: порой подбешивает, острит, может подколоть — но команда его искренне любит и ценит. Не «сарказм ради сарказма», а любящий стёб между своими, как в реальных ЧГК-командах.

**Форма — мягкая, характер — контрастный.** Силуэт остаётся пухлым/круглым/обнимашечным (не переходим в резкую графику) — весь эффект строится на несоответствии мягкой формы и колкого поведения:
- Постоянная деталь лица — приподнятая бровь / полуприкрытые глаза как «resting judgmental face», а не ситуативная эмоция.
- Библиотека из 6-8 узнаваемых поз важнее новых форм тела: скрещенные лапы (самодовольство), медленные хлопки (ехидная похвала), фейспалм (на слабом ответе), поднятая лапа «стоп» (перебивает с поправкой).
- Возможен один фирменный повторяющийся атрибут (например бамбук в зубах как ленивая зубочистка) — деталь для проработки на этапе арта, не зафиксирована жёстко.

**Голос — отдельный визуальный слой.** Реплики панды идут в комикс-style пузыре речи, отличном от обычных системных тостов/баннеров — визуально ясно, что говорит именно ОН, а не интерфейс. Пауза/многоточие перед репликой — комедийный тайминг почти бесплатно (чистая анимация, не новый контент).

**Критический механизм — редкая искренность.** Если панда всегда язвит — это просто неприятный персонаж. Работает только контраст: подавляющее большинство реплик — подколы, и изредка (крупная веха — все 19 приёмов освоены, возврат после разрыва долгого стрика) — искренняя фраза без сарказма. Именно редкость искренности продаёт «команда его ценит», не декларация в тексте.

**Где голос панды используется по функциям приложения:** обратная связь на верный/неверный ответ (T2a), комментарий к личной карте слабых мест (T4 — «опять купился на этот приём»), реакция на стрик/его разрыв (T9), пустые экраны/загрузка.

**Палитра и типографика (не переосмыслены после контекста, остаются в силе):** чёрно-белая база панды + тёплый золотой акцент (отсылка к «Хрустальной/Бриллиантовой сове» — трофеям передачи) + тёмно-зелёный как поддерживающий (сукно игрового стола). Текст вопроса — гуманистический сериф (сигнал «серьёзный контент»), UI-хром — округлый sans-serif. Тёмная тема по умолчанию (ночная/барная культура живых ЧГК-квизов), светлая — как альтернатива.

**Контент-цена:** нужен банк коротких реплик панды под каждый игровой момент (не абзацы — one-liners), написанный самими, без внешних заимствований.

## T5 — пайплайн «Классики» через gotquestions.online (зафиксировано 29.08.2026)

**Смена источника:** db.chgk.info отбракован — самая свежая запись на сайте датирована 18.10.2024 (почти 2 года стагнации), плюс никакого поля сложности вообще. gotquestions.online — актуальные турниры (публикации «часы назад» на момент проверки), 6848 пакетов / 443k+ вопросов / 9759 авторов.

**Технически проще, чем ожидалось:** у сайта нет `robots.txt` вообще (404) — без обязательного `Crawl-delay`. Страница пакета `/pack/<numeric_id>` — Next.js с server-side рендерингом, данные лежат прямо в HTML внутри `self.__next_f.push(...)` как JSON-escaped строка (не нужен браузер/JS для чтения, обычный `curl` отдаёt всё). Внутри — чистый объект на каждый вопрос: `{id, number, text, answer, zachet, nezachet, comment, source, complexity[], teamsCount[]}` + отдельный массив `authors[{questionId, person:{name}}]`.

**Парсинг:** т.к. JSON лежит экранированным (`\"question\":{...}`) внутри JS-строки, простой `json.loads` не берёт напрямую. Решение — вручную найти сбалансированный по фигурным/квадратным скобкам фрагмент (учитывая `\"` как двухсимвольный экранированный литерал), обернуть в кавычки и дважды прогнать через `json.loads` (первый раз снимает экранирование, второй парсит как обычный JSON). Скрипты — `gq_extract.py` (парсер) + `crawl_gotquestions.py` (краулер) в `~/cloude`-scratchpad сессии, при необходимости перенести в репозиторий.

**Важный нюанс формата:** вопросы пакета лежат в **множественном** `"questions":[...]` (полный список всех вопросов пакета), а не в повторяющихся единичных `"question":{...}` — на странице также встречается единичный `"question":{...}` отдельно (не относится к списку, не использовать как основной источник).

**Выборка для первой партии:** случайные ~150 ID пакетов из диапазона 1-7030 (сид зафиксирован для воспроизводимости) → это стабильно даёт больше 5000 вопросов (пакеты разного размера, от ~30 до ~110+ вопросов). Задержка между запросами 0.5 сек (самостоятельно выбранная вежливая пауза, не предписанная сайтом).

**Формат вывода:** тот же контракт T1↔T3 (`id, theme, tournament, question, answer, acceptance, comment, sources[], author`) плюс новое поле `complexity` (два числа или null) — обратно совместимо, старые потребители просто игнорируют лишнее поле. `id` с префиксом `gq-<numeric>`, `theme: null` (не бинго-вопрос).
